# Lory reference catalog

This is the merged catalog of what Lory (a UI and graphics library written in Crow) has to match. It is built from seven survey files, each of which read a set of reference sites and catalogued their components, behaviours and options. Here the same thing found on several sites is one row, rows are grouped by category, and each row names the Lory module that will hold it.

## Sites covered

- Framework examples: Vue examples (https://vuejs.org/examples/), Solid examples (https://www.solidjs.com/examples), Lit docs and playground (https://lit.dev/).
- Headless primitives and themes: Headless UI (https://headlessui.com/), Radix Primitives (https://www.radix-ui.com/primitives), Radix Themes (https://www.radix-ui.com/themes), Radix Icons (https://www.radix-ui.com/icons), Radix Colors (https://www.radix-ui.com/colors).
- Component kits: Semantic UI 2.4 (https://semantic-ui.com/), Vuetify (https://vuetifyjs.com/en/components/all/).
- Motion and scrolling: Motion (https://motion.dev/examples), anime.js (https://animejs.com/documentation), AOS (https://michalsnik.github.io/aos/), fullPage.js (https://alvarotrigo.com/fullPage/examples/).
- Data, tables and drag: Chart.js (https://www.chartjs.org/docs/latest/), TanStack Table (https://tanstack.com/table/latest), Grid.js (https://gridjs.io/), SortableJS (https://sortablejs.github.io/Sortable/).
- Pickers, carousels and widgets: react-datepicker (https://reactdatepicker.com/), TOAST UI (https://ui.toast.com/), react-slick (https://react-slick.neostack.com/docs/example).
- Maps, 3D and audio: Mapbox GL JS examples (https://docs.mapbox.com/mapbox-gl-js/example/), Leaflet (https://leafletjs.com/reference.html), three.js examples and manual (https://threejs.org/examples/), Tone.js (https://tonejs.github.io/).

## How to read it

- One section per category, in a fixed order. Each row is one component or feature; a row that several sites share lists every source, each linked to the page the survey used (site, then the name that site gives it).
- Behaviours to match is a merged, shortened summary: for a row with several sources it is a list of "source: what it does" pieces separated by slashes, and long source texts are cut with an ellipsis. The surveys hold the full detail.
- For the three-family surveys (three.js, Mapbox, Tone.js) the rows are families. Every example or class name is kept: three.js rows carry their example file names at the start of the behaviours cell, and Mapbox and Tone.js rows list each example or class as a linked source.
- Lory home is the module that will hold the row: `lory.gui`, `lory.forms`, `lory.menus`, `lory.overlays`, `lory.disclosure`, `lory.navigation`, `lory.display`, `lory.pickers`, `lory.calendar`, `lory.datatable`, `lory.datagrid`, `lory.drag`, `lory.carousel`, `lory.scrolling`, `lory.motion`, `lory.colors`, `lory.icons`, `lory.geometry`, `lory.space`, `kite.charts`, `map`, `sound` or `examples/<name>`. Where a row spans two modules the main one is named. A few rows sit in a category by what they are but in a module by who will build them (for example a chart tooltip is in the charts category).
- Status is `planned` until a row's module is built. After that it says what is built and tested, and why anything is not; the area's own page (gui.md, forms.md and the rest) has the detail.

## Trust

The surveys could not open many pages (most of these sites render with JavaScript), so they fell back to GitHub sources, sitemaps and the authors' own knowledge. Rows whose behaviour came from page summaries, titles or memory (marked "known", "inferred" or "by title" in the surveys) are leads, not specifications: read the reference page again before building to them. This holds for most of Mapbox, three.js, Tone.js, the react-datepicker examples and the TOAST UI demos. Parity numbers (the checks each survey lists, and the targets in them) are to come from running each reference library, not from the surveys' own claims; where a survey wrote a number from memory, treat it as a guess until a run confirms it.

## Needs from the host

Merged and deduplicated across the seven surveys. Anything Lory cannot do itself has to come from the host (the browser, the headset runtime, or a test harness).

- **Network:** fetching data and assets: map tiles (Mapbox vector and raster, satellite, terrain, sprites, glyphs, OpenStreetMap for Leaflet, WMS, PMTiles range requests), geocoding and directions, Tone.js sample audio, glTF/OBJ/texture and HDR/EXR assets for three.js, remote data for tables (Grid.js server option, TanStack query and router examples, infinite scrolling), remote search, dropdown, tab and tree content (Semantic, TOAST Auto Complete, Tree Ajax), and the app examples (GitHub commits, swapi, REST). A test host can replace these with local mock functions.
- **Access token:** Mapbox GL JS needs an access token and its terms apply to its styles, tiles, geocoder, directions and terrain; Leaflet and open tile sources need none. OpenStreetMap's tile policy limits bulk use.
- **Geolocation:** the position permission prompt (Mapbox locate control, Leaflet `locate`); tests should inject a fake position.
- **Audio:** Web Audio (AudioContext started by a user gesture, AudioWorklet, OfflineAudioContext, look-ahead scheduling), decoding of audio buffers, analysis nodes for waveform and spectrum, positional audio, and media playback for audio and video players.
- **Microphone and camera:** Tone.js `UserMedia`, webcam examples in three.js.
- **Video, media and embeds:** video and iframe embeds (YouTube, Vimeo), video backgrounds, autoplay media, fullscreen and picture-in-picture.
- **Clipboard:** copy and paste for OTP, masked, number and password fields, cell-selection copy and paste in grids and spreadsheets, editor paste of rich content, and copy buttons.
- **Files:** file picker and file drop (file input, file upload, image editor and editor image upload), model and texture loaders, downloads and exports (chart png/jpeg/csv, three.js exporters, Tone Recorder), `toDataURL` and pixel read-back.
- **Fonts and text layout:** font loading and glyph outlines (Lato, Roboto, system, mono and serif stacks, Helvetica for charts), icon fonts and SVG sets (Font Awesome, MDI, Material Icons), text measurement and shaping (wrapping, line splitting, right-to-left, CJK), and number-digit widths for animated numbers.
- **Locale and time:** `Intl`-style number, date and currency formatting, month and weekday names, first day of week, 12/24-hour cycle, ISO week numbers, time zone names and offsets, a "now" clock, and a date library adapter for chart time axes.
- **Keyboard and text input:** key events with `code` and `key`, modifiers, key repeat, IME composition, virtual keyboard focus (also in a headset), autofill and one-time-code fill, selection and caret, tab order, focus ring, global hotkeys, and a native `select` popup for Headless UI's native-element parts.
- **Pointer, touch and gestures:** hover (and no hover on touch), pointer capture, wheel with modifiers, long press, swipe, double tap, multi-touch pinch and rotate, pointer velocity, right-click or `contextmenu` event, pointer lock, pull-to-refresh, outside-click detection across layers.
- **Scrolling:** real scroll position and scroll events, scroll locking, scroll snap, intersection and visibility observation, scroll to anchor, smooth scrolling, and page visibility (pause when hidden).
- **Timers and frames:** a high-resolution frame clock with a frame-rate cap, timers and debounce, delays and transition durations in the hundreds of milliseconds, and the CSS-animation end events replaced by Lory's own timeline.
- **Media queries and display:** viewport size and breakpoints, `prefers-color-scheme`, `prefers-reduced-motion`, wide-gamut (P3) colour, device pixel ratio, safe areas, RTL direction, and mobile or hover-capability detection.
- **Accessibility tree:** ARIA roles, live regions, `aria-current` and visually hidden text; a canvas needs a parallel DOM mirror or a host accessibility bridge.
- **History and URL:** hash, `pushState` and `popstate`, `location.hash` for anchors and routing, URL search params, and opening URL schemes (not possible in a headset).
- **Storage:** local storage (todo apps) and cookies or storage for a remembered setting (TOAST Auto Complete).
- **DOM-like geometry:** element rectangles for placement and layout animation, collision against the viewport, SVG path length and point-at-length, and CSS colour parsing (rgb, hsl, named, oklch).
- **Canvas and graphics features:** gradients, patterns, dashed strokes, clips, rounded rectangles with per-corner radii, point-style glyphs, canvas-as-texture and HTML-to-texture, 3D transforms and perspective, and the WebGL2 feature set (instancing, array and 3D textures, uniform buffers, multiple render targets, float and depth textures, compressed formats). WebGPU-only examples (`webgpu_*`) cannot be matched by a WebGL renderer.
- **WebXR:** immersive VR and AR sessions, hand tracking, hit test, plane detection, camera access and layers.
- **Workers and WASM:** off-main-thread row models, OffscreenCanvas, decoder workers (Draco, KTX2, Basis), audio worklets, and physics engines in WASM.
- **Dialog and top layer:** a modal rendered at the document body level with a full-screen mask, focus trap, inert outside content and focus return.
- **Test helpers:** a seedable random source (Chart.js samples, scramble text, random stagger, Etch A Sketch colours) and fixed sample data for parity runs.
